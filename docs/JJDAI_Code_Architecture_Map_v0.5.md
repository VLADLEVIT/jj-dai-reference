## The honest sentence

v0.4.1 closed the identity gap. v0.5-dev5 closed the cryptographic boundary. v0.5-dev6 made replication sound. v0.5.1 closed P1 mechanisms. v0.5.2 added the Monero anchor. v0.5.3 closed the COMPOSITION GAP: one BeingRuntime drives every organ through one witnessed lifecycle over one identity, and POST /v1/tasks returns the full DecisionTrace — including the honest endings REFUSED, FAILED, FATE_UNKNOWN and CONTAINED. v0.5.4 made verification ADVERSARIAL: RFC 9381 ECVRF (vector-pinned) drives transcript-bound panel sortition nobody can grind; verdicts are sealed before any are shown; silence and fraud become witnessed, offline-verifiable evidence; and the daemon holds its first operational boundary — per-identity rate limiting whose systematic abuse is itself witnessed. v0.5.5 is the SECURITY-ALPHA: role-based authorization (default-deny, longest-prefix), certificate revocation that beats identity, /healthz + /metrics, the challenge round carried over mTLS, a production PKI with an offline root, optional TPM-sealed keystores, a hardened systemd unit and an operator runbook — the kit to stand up testnet-0 on Ubuntu. v0.6.1 propagates INV-9 v1.1: the invariant is reworded from “non-acting” to “non-executive, not causally inert” — the executive prohibition is unchanged, the sanctioned reflexive path (J-Lens → Viveka → Chitta, pre-finalization) is named, and direct mutation of an output or verdict remains forbidden; the reflexive loop itself is a Ф3 runtime deliverable (roadmap r5), so the archive-only runtime stays compliant. v0.6.2 ports the deployment kit to macOS (roadmap Ф0): a launchd daemon template, Keychain sealing of the keystore passphrase under the explicitly documented macOS Keychain degraded profile (non-SE-resident); a true Secure Enclave-backed profile is reserved as a separate future attestation profile, a bootstrap that enforces the 24/7 power discipline of a laptop-chassis server, RUNBOOK-macOS, and an SECURITY.md triage template — with unit acceptance pinning flag parity between the systemd and launchd paths so the two kits cannot drift apart silently. v0.6.3 answers the external audit of v0.6.2: the systemd watchdog that would have killed a healthy node every 60 s is removed until sd_notify lands; /opt/jjdai is root-owned on both platforms so the daemon can no longer rewrite its own code; the macOS profile is renamed to “macOS Keychain degraded profile (non-SE-resident)” with a true Secure Enclave-backed profile reserved for the future and an M-LIVE operational-evidence checklist added; hand-written docs are pinned to the code by a release-integrity test (versions, outgrown claims, acceptance count, AGPL placeholder loudness). v0.6.4 opens the Ф0 isolation and ingress work. Karma gains an ISOLATION-PROFILE SEAM: the reference sandbox becomes a named profile, and a second profile, wasm-wasi, executes a FIXED SET of precompiled WASI modules pinned by digest — an allow-list boundary enforced by the runtime instead of a deny-list subtracted from the kernel, at the deliberate cost of arbitrary argv. The seam FAILS CLOSED: a declared profile whose runtime is absent refuses the action and says so in capabilities, and is never downgraded to a weaker profile — a record written after the fact restores no boundary, and by INV-9 the witness cannot intervene. Refusal and execution are witnessed alike; the difference between them is whether the hand moved. Ingress gains the three caps that must exist before the network is opened to anyone who is not us: a body ceiling enforced before the body is read, a non-blocking concurrency ceiling answering 503 rather than queueing work the node has not agreed to hold, and a per-connection clock. The rate-limit budget moves from the client ADDRESS to the certificate IDENTITY, so one certificate holder can no longer reset their own budget by changing address and a whole NAT is no longer charged to one bucket. The drop was re-cut after external review: the concurrency ceiling now admits on the accept loop, before a worker thread exists, because taking the slot inside the handler bounded request PROCESSING and not thread CREATION — and the check written for it tested the semaphore rather than the claim. Refusals are handled by one bounded worker that drains before closing, so an overloaded node still answers 503 instead of resetting the connection and leaving the caller unable to tell overload from death. wasm-wasi readiness is now computed per tool against real modules and digests, so a declared capability is an executable one. A live opt-in group proves the boundary against a real runtime and fails loudly without one. Known-and-scheduled: /readyz and the liveness split, sd_notify with the watchdog return, Prometheus alert rules, the adapters restructure, and the canonical AGPL text remain open, tracked items. v0.6.5 lifts the engine seam into jjdai/adapters/: EngineBackend Protocol v1 is declared WHOLE, so an unimplemented method exists and raises a typed NotSupported instead of being absent — a hole invites every caller to grow its own probe and its own silent fallback, and a silent fallback is how a node comes to believe it has a capability it does not have. Capability is DERIVED from what a driver actually overrides rather than hand-declared, so a manifest cannot drift from the code. Model families arrive as declarative profiles validated against a versioned schema that refuses unknown keys, and a ModelArtifactManifest carries profile → JCS → hash → signature. Separately, the witness plane gains a VOCABULARY: enum tokens, integers and digests cross into it, prose does not — an append-only replicated store that accepts free text is both a covert channel and an unbounded write, so refusal reasons became versioned codes. The record kinds of cross-cutting track IV (SESSION_OPEN, SESSION_CLOSE, LEDGER_ANCHOR, SNAPSHOT) and the nullable session_id / ir_schema_version fields are RESERVED in the canonical enum before genesis and refuse to be emitted until their semantics land in Ф2–Ф3.

Said plainly: authorization is transport-role based (peer/admin/anonymous from the mTLS CN), not yet capability- or guardian ballot based; certificate revocation is serial-list based; Karma now carries an isolation-profile seam with a wasm-wasi profile beside the reference sandbox, but this build ships the mechanism and no compiled toolset, so in practice execution is still the reference fence, and microvm is reserved and deliberately unimplemented; the knowledge store is retrieval-baseline, not a knowledge graph; and DIIP remains deliberately absent. This is an alpha to operate among known operators, not to expose to untrusted load.
