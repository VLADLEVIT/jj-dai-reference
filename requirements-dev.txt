# PYTHON TEST DEPENDENCIES — pinned by version and by hash.
#
# SCOPE, stated first, because this file used to call itself "the CI
# toolchain" and that claimed more than it delivered. A partial pin
# described as a whole one is worse than an honest gap: it stops anyone
# looking. What a CI job actually depends on, and where each stands:
#
#   * the Python test dependencies below — pinned by VERSION and by HASH,
#     installed with --require-hashes;
#   * the workflow's GitHub Actions — pinned by full COMMIT SHA in
#     .github/workflows/ci.yml. A `@v4` tag is a branch in all but name;
#   * `setuptools` in [build-system].requires — pinned by EXACT VERSION,
#     but NOT by hash: PEP 517 gives `requires` nowhere to put one. This
#     is the one input still resolved by name at build time, and it is
#     carried as open debt under v0.6.10 (reproducible build).
#
#
# This is NOT a runtime dependency list. The JJ DAI core is stdlib-only and
# installs nothing; `scripts/run_acceptance.py` proves that by running the
# whole hermetic suite on a bare interpreter, and CI runs it on every job
# for exactly that reason. What is pinned here is the collector CI uses to
# produce its result.
#
# WHY PINNED. `pip install pytest` resolves against whatever PyPI serves that
# morning. A green CI run then means "this tree passed under an unknown
# version of an unknown collector" — which is not the claim the badge makes.
# The same argument the project already applied to model artefacts and to the
# wasm toolset applies to the tool that produces the evidence.
#
# WHY HASHED. A version pin binds a NAME to a NUMBER; the hash binds it to
# BYTES. `--require-hashes` also forces every transitive dependency to be
# pinned, which is the property worth having: an unpinned transitive is the
# same hole one level down.
#
# HOW TO CHANGE ONE. Never edit a hash by hand. Run, on the lowest supported
# interpreter:
#
#     pip download --no-cache-dir -d /tmp/dl <pkg>==<ver>
#     pip hash /tmp/dl/*.whl
#
# and paste the result. A hash you cannot reproduce from a download is a
# hash nobody verified.
#
# Regenerating: see `scripts/gen_sbom.py`, which reads this file and records
# these components in the SBOM — together with the pinned Actions, and with
# the one remaining unhashed input named, so the bill of materials is not
# read as a complete one.

# exceptiongroup's OWN dependency, and the reason this file needs it: in
# --require-hashes mode pip demands that EVERY requirement it resolves is
# pinned with == and hashed, transitive ones included. Leaving this out makes
# the 3.10 job fail at `pip install` with "these do not: typing-extensions
# >=4.6.0" while 3.11 and 3.12 pass — exceptiongroup is installed only below
# 3.11, so only there is this ever requested.
#
# The gap is invisible to `scripts/run_acceptance.py`, which is stdlib-only
# and installs nothing: the acceptance run this package certifies cannot see
# an incomplete pin file. Only the pytest jobs can, which is why this has now
# been lost once and re-added once.
#
# Both artefacts are named, wheel and sdist, so the pin holds whichever pip
# picks; the wheel digest was cross-checked against the one PyPI publishes
# rather than trusting the bytes that arrived.
