Purpose

This document defines a conformance specification. An engine is certified against it once — after which the NodeDaemon and ChampionRegistry can treat vLLM, SGLang, DwarfStar-plus-sidecar, or any custom runtime as interchangeable node engines. Certification is not a benchmark. It is a guarantee that the engine speaks one interface, loads only declared and verifiable weights, and emits a witness record for every inference it performs.

Normative keywords MUST · MUST NOT · SHOULD · MAY are used per RFC 2119.

Conformance profiles

An NE is certified against exactly one profile, per node role. Specialization is available in every profile — the profiles differ in how specialization is carried, not whether it exists.

Determinism levels

Declared by the NE, verified in C2:

  • attestedOutput is signed but not bit-reproducible. Default for cross-engine operation.
  • reprod.Bit-identical output given a pinned Engine Fingerprint. The NE MUST document the pinning set.
Provenance ≠ Consensus

A Light-node closes the origin gap — who computed this — but not the corroboration gap — do independent parties agree. Local answers are therefore attested, single-source. Network answers add independence-weighted consensus. The sākṣī — the witness — is real only where corroboration is.

Contract 1

C1Interface

One uniform surface so NodeDaemon and ChampionRegistry stay engine-agnostic.

Normative requirements

  • C1.1The NE MUST expose an HTTP endpoint implementing the JJ DAI Inference Interface (JII) — a /v1/messages-class envelope plus mandatory JJ DAI metadata.
  • C1.2The NE MUST implement GET /capabilities returning a static capability descriptor.
  • C1.3Every request MUST carry substrate_id, adapter_ids[], sampling (pinned: seed, temperature, top_p, top_k, max_tokens), request_id (UUIDv7), and nonce (128-bit). The NE MUST echo request_id and nonce verbatim.
  • C1.4The NE MUST accept an opaque champion_context tag (topic / champion routing) and echo it for attribution.
  • C1.5The NE MUST support both streaming (SSE) and unary responses.
  • C1.6The NE MUST return the Provenance Descriptor (C2) and Witness Receipt (C3) with every completed inference.
  • C1.7The NE SHOULD support cooperative cancellation and MUST NOT silently mutate sampling params — any override returns 409 SAMPLING_UNSATISFIABLE.
  • C1.8Errors MUST use the normative code set. An NE that cannot emit a witness receipt MUST fail closed with 503 — never return an un-witnessed answer.

Contract 2

C2Substrate + Provenance

Load only declared base and adapters, with content-addressed, verifiable identity — enabling attribution and, where declared, reproducibility.

Normative requirements

  • C2.1Every substrate MUST be identified by a Merkle root over its weight-shard manifest, prefixed with the quantization descriptor hash — quantization is part of identity because it changes outputs.
  • C2.2At load, the NE MUST recompute shard hashes, rebuild the root, and compare against the declared substrate_id. On mismatch it MUST refuse to serve (422).
  • C2.3(Profile A) Every adapter MUST be identified by adapter_id = sha256(canonical(weights ‖ base_compat_tag ‖ {type, rank})). The NE MUST verify it and confirm base_compat_tag == substrate_id before activation.
  • C2.4The NE MUST emit a Provenance Descriptor per inference and declare its determinism_level. The Engine Fingerprint is H(engine ‖ version ‖ backend ‖ kernels ‖ quant ‖ hardware_class).
  • C2.5Substrate and adapter artifacts MUST be immutable and content-addressed. Upgrades produce new IDs (pull-by-choice); in-place mutation is forbidden. Aligns with Manifesto Art. VII — history is append-only.
  • C2.6The NE MUST produce a Merkle inclusion proof that any given shard or adapter belongs to the declared set — reusing the sqlite-vec + Merkle machinery.

Schema — manifest & provenance descriptor

// Weight manifest (defines substrate_id)
{
  "quant": "iq2_xxs+q2_k",                  // part of identity
  "quant_hash": "sha256:…",
  "shards": [
    { "path": "model-00001.gguf", "sha256": "…", "bytes": 4.2e9 }
  ],
  "merkle_root": "sha256:9f2b…"              // == substrate_id (post quant-prefix)
}

// Provenance Descriptor (per inference)
{
  "substrate_id": "sha256:9f2b…",
  "adapter_ids": ["sha256:1a…"],
  "engine_fingerprint": "sha256:c4…",
  "determinism_level": "attested",
  "sampling": { "seed": 42, "temperature": 0.0, "top_p": 1.0 },
  "hardware_class": "apple-m3-max-128g"
}

Reference pseudocode

def verify_substrate(manifest, declared_id):
    leaves = sorted(shard.sha256 for shard in manifest.shards)
    root = merkle_root([sha256(manifest.quant)] + leaves)
    if root != declared_id:
        raise ProvenanceMismatch(422)
    return root

def verify_adapter(adapter, substrate_id):
    aid = sha256(canonical(adapter.weights, adapter.base_compat_tag,
                           {"type": adapter.type, "rank": adapter.rank}))
    if aid != adapter.id or adapter.base_compat_tag != substrate_id:
        raise ProvenanceMismatch(422)

def build_provenance(cfg, active_adapters):
    return ProvenanceDescriptor(
        substrate_id=cfg.substrate_id,
        adapter_ids=[a.id for a in active_adapters],
        engine_fingerprint=engine_fingerprint(),
        determinism_level=cfg.determinism_level,
        sampling=cfg.sampling,
        hardware_class=cfg.hardware_class)

Acceptance criteria

T-C2-aFlip one byte in any shard → verify_substrate MUST raise 422; model MUST NOT load.
T-C2-bLoad adapter whose base_compat_tag ≠ substrate_id → MUST reject with 422.
T-C2-cRequest inclusion proof for a known shard → MUST verify; proof for an absent shard MUST fail.
T-C2-dOn a reproducible NE, two runs with identical Engine Fingerprint + sampling → identical output (bridges to T-C1-c).
Contract 3

C3Witness

Every inference emits one signed, hash-chained record. An engine that cannot be instrumented to witness cannot be a consensus node.

Normative requirements

  • C3.1Per inference the NE (or its sidecar) MUST append one Witness Record to a per-node hash chain: this_hash = H(prev_hash ‖ canonical(record_body)).
  • C3.2The chain MUST store commitments, not plaintext: request_commitment and response_commitment are hashes. Plaintext stays local; only commitments enter the chain.
  • C3.3Records MUST be signed with the node key (Ed25519); node_id = H(pubkey); index is monotonic per node.
  • C3.4The NE MUST periodically anchor the local Merkle root of new records to the shared witness ledger, and SHOULD anchor to an external timestamp authority (OpenTimestamps). Anchoring the root only batches many inferences into one write — killing chain-spam and cheap Sybil.
  • C3.5Each record MUST carry provenance_hash = H(Provenance Descriptor) so consensus can group comparable computations.
  • C3.6Because cross-engine output is non-deterministic, consensus MUST operate over response_commitment plus a semantic representation, independence-weighted — never bit-exact equality across engines.
  • C3.7The chain MUST be replay-verifiable: any mutation breaks a hash and is detectable by re-walking the chain.

Schema — witness record & receipt

// Witness Record (record_body is what gets hashed & signed)
{
  "index": 10427,
  "prev_hash": "sha256:aa…",
  "timestamp": "2026-07-03T12:00:00Z",
  "node_id": "sha256:pub…",
  "request_commitment": "sha256:…",
  "response_commitment": "sha256:…",
  "provenance_hash": "sha256:…",
  "semantic_digest": "b64:…",        // low-dim embedding for C3.6
  "this_hash": "sha256:bb…",         // H(prev_hash ‖ canonical(body))
  "sig": "ed25519:…"                 // over this_hash
}

// Witness Receipt (returned inline per C1.6)
{ "index": 10427, "this_hash": "sha256:bb…",
  "anchored": false, "anchor_eta": "batch@root" }

Reference pseudocode

def emit_witness(req, resp, prov, keypair, chain):
    body = {
      "index": chain.next_index(),
      "prev_hash": chain.head_hash(),
      "timestamp": now_utc(),
      "node_id": node_id(keypair.pub),
      "request_commitment": sha256(canonical(req)),
      "response_commitment": sha256(canonical(resp)),
      "provenance_hash": sha256(canonical(prov)),
      "semantic_digest": embed(resp.output),
    }
    body["this_hash"] = sha256(chain.head_hash() + canonical(body))
    rec = sign(body, keypair)          # Ed25519 over this_hash
    chain.append(rec)                  # fail-closed: raise 503 on failure
    return WitnessReceipt(rec.index, body["this_hash"])

def anchor_root(chain, ledger, ots):
    root = merkle_root(chain.since_last_anchor())
    ledger.submit(node_id, root)       # C3.4 shared ledger
    ots.stamp(root)                    # external timestamp authority

def verify_chain(chain):
    h = GENESIS
    for rec in chain:
        body = strip(rec, "sig")
        assert rec.this_hash == sha256(h + canonical(body))
        assert verify_sig(rec)
        h = rec.this_hash

Acceptance criteria

T-C3-aRun N inferences → verify_chain passes; indices contiguous and monotonic.
T-C3-bMutate any stored record → verify_chain MUST fail at that index.
T-C3-cOnly commitments present in chain — assert no plaintext request/response bytes appear in any record.
T-C3-dAfter anchor, inclusion proof against the anchored root MUST verify; OTS proof upgrades to confirmed after the authority's cycle.
T-C3-eTwo nodes, same substrate + prompt, different engines → response_commitment differs (expected), yet both group by identical provenance_hash-family and feed consensus via semantic_digest.

Composition & Certification

An engine is certified for a profile once it passes the full test set. The NodeDaemon MUST refuse to enroll a node whose engine_fingerprint is not in the registry for its declared role.

Appendix A

Canonicalization

All canonical(...) hashing MUST use RFC 8785 JSON Canonicalization Scheme (JCS): UTF-8, lexicographically sorted keys, no insignificant whitespace, canonical number forms. Hash is SHA-256 unless a substrate declares otherwise.

Appendix B · Worked example

DwarfStar → Profile B / B-spec

DwarfStar has no adapter serving and no native witness log. It maps to Profile B and B-spec only, and only with a mandatory witness-sidecar. It is not disqualified from specialization — only from the hot-adapter mechanism of Profile A.

C1 · Interface

Wrap its OpenAI/Anthropic-compatible server behind a thin JII shim that injects and echoes nonce, request_id, and champion_context. FEASIBLE

C2 · Substrate + Provenance

It already loads a single content-addressed GGUF set → compute substrate_id over its shards; determinism_level: attested (Metal kernels, non-reproducible across hardware). For B-spec, a LoRA/DoRA merged offline into a new frozen GGUF is served as a distinct substrate_id — specialized knowledge inside, no hot adapters. CONFORMANT (B / B-spec)

C3 · Witness

The sidecar hooks pre- and post- its server API to emit, sign, and chain records, and to batch-anchor roots. DwarfStar bare is NON-CONFORMANT — DwarfStar + sidecar is PROFILE-B CONFORMANT

Profile A · Adapter serving

DwarfStar has no in-forward-pass LoRA math, so an adapter_id cannot be routed to it hot. Multi-adapter batching (C2.3) is unavailable. DISQUALIFIED (A)

Appendix C

Where specialization lives

Specialization occupies three distinct spaces. Conflating them is what made the original "DwarfStar can't specialize" claim wrong — it can, in two of the three.

SpaceMechanismChanges weights?DwarfStarRegistry status
ContextSystem prompt, few-shot, RAGNo — conditions inputYesPer-request hash, not an adapter
ActivationSteering vectors (residual-stream directions)No — shifts activationsYes, nativeOne direction; not low-rank
WeightLoRA / DoRA: W·x → W·x + s·B·A·xYes — alters projectionNo (hot); Yes if bakedFirst-class adapter_id artifact
The precise line

A node can specialize without vLLM — via context, steering, or a baked substrate. What DwarfStar cannot do is specialize through the hot weight-adapter mechanism that the architecture names as an adapter_id: a content-addressed, verified, swappable, batchable object. That mechanism is Profile A only.
